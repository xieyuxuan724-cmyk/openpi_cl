# 2026-10-28 代码改动说明

本文记录今天对 `openpi_cl` 的代码修改，以当前最终实现为准。
覆盖提交 `45d1a8d`、`ad70031`、`1ff7924`、`e77c3e3`、`e68a88a`、`8825ca7`。

## 1. 新增四任务持续学习入口

涉及文件：

- `experiments/__init__.py`
- `experiments/continual/__init__.py`
- `experiments/continual/run.py`
- `experiments/continual/protocol.py`

将持续学习逻辑集中到 `experiments/continual/`，训练底层仍复用 `scripts/train.py`。
新增 `plan`、`train`、`serve` 三种入口，分别用于查看配置、训练一个阶段、启动模型服务。

具体变化：

- 支持 T1 → T2 → T3 → T4 顺序训练。
- T1 从指定的 π0.5 预训练权重初始化；后续阶段加载上一阶段的完整模型与同一组 LoRA。
- 校验上一阶段的编号、配置身份、归一化文件哈希和阶段末检查点编号。
- 跨阶段加载前检查 LoRA 参数是否存在，避免适配器被遗漏或重新初始化。
- 同阶段支持 `--resume`，并检查恢复配置是否一致。
- 新增 `manifest.json`，记录训练配置、数据划分哈希、归一化哈希、回放索引、代码提交、工作区差异哈希和依赖版本。
- 正式检查点使用独立配置名称 `cl_pi05_continual_v2`，与旧 smoke 配置区分。

最终默认配置：π0.5、语言与动作 LoRA、视觉全量微调、batch=8、每阶段 10000 步。
保留 `--freeze-vision` 和 `--batch-size`，允许显式配置小显存对照。
优化器为 AdamW，峰值学习率 2.5e-5，warmup 500 步，余弦衰减到 2.5e-6。

## 2. 实现不回放和 20% 回放两种训练方式

涉及文件：

- `experiments/continual/protocol.py`
- `experiments/continual/run.py`
- `src/openpi/training/config.py`
- `src/openpi/training/data_loader.py`

新增两种方法：

| 方法 | 实现 |
|---|---|
| `sequential` | 只使用当前任务的训练数据 |
| `replay` | 每个旧任务固定保留其训练样本起点的 20%，与当前任务混合训练 |

具体变化：

- `replay_plan()` 按各任务训练帧数计算预算，默认向下取整取 20%。
- 回放样本无放回抽取；任务对应的随机种子与后续阶段无关，确保缓冲区不会随着阶段推进重新抽样。
- `DataConfig` 增加 `frame_indices`、`current_frame_count`、`replay_group_sizes`。
- 数据加载器使用 `Subset` 限制实际取样的起点。
- 新增 `BalancedReplaySampler`：每个 batch 严格一半当前任务、一半旧任务，要求 batch 为偶数。
- 旧任务部分先等概率选择任务，再在对应缓冲区内均匀采样，避免大任务占据更多回放机会。
- 保留 `--replay-budget`，用于显式指定固定数量；当前主设置使用 `--replay-fraction 0.2`。
- 新增 `replay_audit()`，同时统计样本起点数量和独立动作标签覆盖量。

这里的 20% 指动作块起点：一个样本带后续 10 步动作标签，因此独立动作标签覆盖率可能超过 20%。
代码记录这个差异；底层完整数据文件仍保留在数据盘，通过索引限制训练访问。

## 3. 将固定 T1 归一化改成按任务归一化

涉及文件：

- `experiments/continual/normalization.py`（新增）
- `experiments/continual/data.py`（新增）
- `experiments/continual/run.py`
- `src/openpi/training/config.py`
- `src/openpi/training/data_loader.py`
- `src/openpi/training/checkpoints.py`

修改前：四任务流程共用 T1 的统计量。

修改后：每个任务只用自己的训练轨迹计算统计量，后续固定使用；验证轨迹不参与统计。

具体变化：

- `normalization.py` 生成每任务独立的 `norm_stats.json` 和 `metadata.json`。
- 动作统计与训练使用相同的十步动作块，轨迹末尾重复最后一帧，不跨轨迹取动作。
- 统计文件保存任务、训练轨迹编号、动作长度、数据划分哈希、数值数据哈希与统计文件哈希。
- 已存在的统计目录拒绝覆盖，防止训练中途悄悄更换尺度。
- `validate_assets()` 只要求当前及已学任务的统计文件，未来任务的统计文件可以尚不存在。
- 新增 `ContinualLiberoDataConfig`，支持显式选择 `quantile` 或 `zscore`。
- π0.5 默认仍使用分位数缩放；按任务独立统计的组织方式参考作者代码，数值公式没有强行照搬 π0。
- `DataConfig` 增加 `task_norm_stats` 和 `episode_norm_keys`。
- 新增 `TaskNormalizedDataset`：在重排字段移除原始轨迹编号之前，根据 `episode_index` 选择统计量。
- 旧任务回放继续使用旧任务自己的统计量，不使用当前任务的尺度。
- 检查点保存所有已学任务的统计量，支持之后逐任务评测。

## 4. 完善逐任务评测和服务绑定

涉及文件：

- `experiments/continual/evaluate.py`（新增）
- `experiments/continual/run.py`
- `experiments/continual/protocol.py`
- `examples/libero/main.py`

具体变化：

- 新增 `evaluate.py`，从检查点的 manifest 重建服务配置，依次测试该阶段所有已学任务。
- 服务入口增加 `--eval-task`，加载对应任务的归一化文件。
- 服务元数据包含阶段、检查点路径、配置身份、评测任务和统计量哈希。
- 客户端启动评测前核对这些字段，防止同一模型使用错误任务的归一化。
- 同一阶段所有任务使用同一检查点，仅切换任务相关的统计量。
- 按任务文本匹配 LIBERO 任务，支持明确指定任务与初始状态编号范围。
- 每回合写入 JSONL，记录成功与否、任务、阶段、检查点、初始状态编号、归一化哈希和评测设置。
- 结果文件拒绝静默覆盖；重跑可通过 `--run-tag` 使用新输出目录。
- 环境或推理错误直接报错，不当作一次普通策略失败。
- 使用 `finally` 关闭仿真环境，评测驱动负责结束自己启动的模型服务。
- 默认每个任务仅保存前 3 个视频，支持设为 0；全部回合仍保留结构化结果。
- 仿真子进程默认采用 OSMesa CPU 渲染，允许通过环境变量选择 EGL。

## 5. 新增数据审计和两组结果比较

涉及文件：

- `experiments/continual/analyze.py`
- `experiments/continual/compare.py`（新增）
- `experiments/continual/protocol.py`

`analyze.py` 提供数据审计与单组结果汇总：

- 统计各任务训练/验证轨迹数、训练帧数、动作范围、归一化范围和超范围比例。
- 输出完整成功率矩阵、对角线平均成功率、最终平均成功率和最终遗忘。
- 计算各旧任务跨后续阶段的平均 NBT，并明确输出两种任务平均分母约定。
- 保留负遗忘值，表示学习后续任务后旧任务表现改善。
- 归一化 NBT 遇到初始成功率为零时返回 `null`。
- 为各成功率单元格计算 Wilson 95% 区间。
- 拒绝重复回合、不完整矩阵、不匹配的初始状态编号、归一化变化以及同一阶段混用检查点。

`compare.py` 提供不回放与 20% 回放的配对比较：

- 按训练种子配对，要求两组种子集合一致。
- 核对除方法和回放设置之外的训练参数，以及评测条件、初始状态编号和归一化哈希。
- 输出各指标的跨种子均值、样本标准差及回放减去不回放的配对差值。
- 只有一个种子时，标准差返回 `null`。

## 6. 增加训练数值异常检查

涉及文件：`scripts/train.py`。

具体变化：

- 增加训练参数数量日志及可选的运行 manifest 保存。
- 新增 `tree_all_finite()`，检查参数树中的数组是否包含 NaN/Inf。
- 每步检查 loss、梯度、优化器更新量和更新后的可训练参数。
- 发现非有限值时记录异常类别并停止训练，避免将异常训练结果继续保存为阶段末模型。
- 检查点写入前检查剩余数据盘空间。
- JAX 编译缓存遵循数据盘配置。

更完整的有限值检查于今天提交为 `8825ca7`。

## 7. 统一数据盘存储和检查点保留策略

涉及文件：

- `experiments/continual/storage.py`（新增）
- `experiments/continual/run.py`
- `experiments/continual/analyze.py`
- `scripts/train.py`
- `examples/libero/main.py`

具体变化：

- 新增统一启动包装器，在导入训练库之前设置临时目录与缓存环境变量。
- 将临时文件、框架缓存、日志、检查点、报告、视频和 LIBERO 配置指向数据盘。
- 检查挂载文件系统、符号链接解析路径、写权限和可用空间，拒绝检查点写到系统盘或管理目录外。
- 启动命令保存 stdout/stderr 日志和运行信息。
- 每阶段仍定期保存，但设置 `keep_period=None`，结合 `max_to_keep=1` 只保留该阶段最新检查点。
- 四个阶段使用独立目录，因此一组完整实验最终保留四份阶段末模型。
- 共享存储模块兼容 Python 3.10 仿真环境。

## 8. 新增独立仿真环境的安装与检查代码

涉及文件：

- `experiments/continual/setup_sim.sh`（新增）
- `experiments/continual/sim_requirements.txt`（新增）
- `experiments/continual/sim_smoke.py`（新增）

具体变化：

- 安装脚本在数据盘建立独立 Python 3.10 venv，与 Python 3.11 训练环境分离。
- 固定核心仿真依赖，包括 robosuite、MuJoCo、NumPy、Numba、SciPy 等。
- 使用 CPU 版 PyTorch 读取 LIBERO 初始状态；模型推理由另一环境中的服务负责。
- 安装仓库内的 LIBERO 与 openpi-client，并执行依赖冲突检查。
- 生成 LIBERO 路径配置、完整依赖版本记录，以及 `examples/libero/.venv` 兼容链接。
- 支持通过 `SIM_INDEX_URL` 指定下载镜像。
- `sim_smoke.py` 依次检查四任务的初始状态读取、场景加载、双相机图像和动作执行，并保存报告与截图。
